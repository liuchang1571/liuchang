## 一、程序跑起来的顺序

### 1. 上电，main() 跑一遍

`Core/Src/main.c` 里的 `main()` 做这些事：

```
HAL_Init()                → 配置 1ms 心跳（TIM2）
SystemClock_Config()      → 168MHz
MX_GPIO_Init()            → 引脚
MX_DMA_Init()             → DMA
MX_CAN1_Init()            → CAN1（本工程没用）
MX_CAN2_Init()            → CAN2（重要！但还没"点火"）
MX_USART1_UART_Init()     → 串口1（本工程没用，留着以后打印）
MX_USART3_UART_Init()     → 串口3 = 接遥控器接收机（重要！）
osKernelInitialize()      → 准备 FreeRTOS
MX_FREERTOS_Init()        → 创建 4 个任务
osKernelStart()           → 启动调度器，从此 main() 再也不返回
```

> ⚠️ **关键理解**：`MX_CAN2_Init()` 之后 CAN **还是死的**。
> 它只是把寄存器参数配好了，CAN 还在"初始化模式"，不发也不收。
> 真正让它工作的是后面 `BSP_CAN_Init()` 里的 `HAL_CAN_Start()`。

### 2. FreeRTOS 的 4 个任务

任务都写在 `Core/Src/freertos.c`。

| 任务名 | 函数 | 优先级 | 干什么 | 周期 |
|---|---|---|---|---|
| `Init_Task` | `StartTask04` | **最高（Realtime）** | 给外设"点火"，做完就自杀 | 只跑一次 |
| `Chassis_Task` | `StartTask02` | High | 整个车的大脑 | **1ms** |
| `defaultTask` | `StartDefaultTask` | Normal | 查电机掉线 | 10ms |
| `CAN_Rx_Task` | `StartTask03` | AboveNormal | **没用**，自己挂起了 | — |

**为什么 `Init_Task` 优先级必须最高？**
调度器一启动，优先级最高的任务先跑。如果不把 `Init_Task` 提到最高，
底盘任务会先跑起来 —— 此时 CAN 还没 Start、PID 参数还是 0，
结果就是"上电前几毫秒发了一堆乱指令"。

### 3. Init_Task 干的 5 件事（`freertos.c:213` 附近）

```c
BSP_CAN_Init();        /* ① CAN2：配过滤器 → HAL_CAN_Start → 开接收中断 */
Task_RC_Init();        /* ② 串口3：开 DMA 接收 → 开空闲中断 */
Task_Chassis_Init();   /* ③ 给 4 个电机对象填 PID 参数 */
g_sys_ready = 1;       /* ④ 放行：告诉底盘任务"外设都活了" */
vTaskDelete(NULL);     /* ⑤ 自己做完了，退出 */
```

### 4. 之后就是底盘任务的 1ms 循环，一直跑到断电

```
Task_Chassis_Loop()  （在 task_chassis.c）
  ① Task_RC_Loop()        处理遥控器
  ② 摇杆 → vx / steer     归一化、死区、乘上限
  ③ Ackermann_Solve()     运动解算（现在是空壳）
  ④ 写 target_rpm / target_raw
  ⑤ PID ×4               后轮速度环2个 + 前轮位置环2个
  ⑥ CAN 发送              0x200 + 0x1FF
  ⑦ vTaskDelayUntil(1ms)
```

### 5. 目录结构和每一层的职责

```
App/
├── Config/
│   ├── config.h        ← 参数总表（想改数值只改这里）
│   └── config.c        ← 全局变量的定义
├── Bsp/                ← 直接操作硬件寄存器那一层
│   ├── bsp_rc.c        ← 串口 + DMA + 空闲中断，只管搬字节
│   └── bsp_can.c       ← CAN 收发，只管塞字节/拆字节
├── Driver/             ← 协议 + 控制算法
│   ├── drv_dbus.c      ← 18 字节 → 摇杆数值
│   ├── drv_motor.c     ← 3508 速度环
│   └── drv_steer.c     ← 6020 位置环
├── Task/               ← 业务逻辑
│   ├── task_rc.c       ← 关控判断 + 摇杆回中
│   └── task_chassis.c  ← 1kHz 主循环
└── Algorithm/
    └── ackermann.c     ← 运动解算（空壳，等你填）
```

**分层的意义**：以后换接收机型号，只改 `bsp_rc.c`；
换电机型号，只改 `drv_motor.c`；调参，只改 `config.h`。
其它文件都不用动。

## 二、C 语法小抄（卡住的时候回来查）

### `0U` 的那个 `U` 是什么？

```c
uint8_t i = 0U;
```

`U` = **unsigned（无符号）**，是写给编译器看**后缀**。

| 写法 | 类型 | 范围 |
|---|---|---|
| `0` | `int`（有符号） | -21亿 ~ +21亿 |
| `0U` | `unsigned int`（无符号） | 0 ~ +42亿 |

**你完全可以只写 `0`，一样跑。** 本工程的代码里已经全部不用 `U` 了，
看到别人的代码里有 `0U`，当成 `0` 理解就行。

### `#if` 和 `if` 有什么区别？

```c
#if (BENCH_TEST == 1)
    这段代码
#endif
```

| | 什么时候判断 | 不满足时会怎样 |
|---|---|---|
| `#if` | **编译时**（你写代码的时候） | 这段代码**根本不会被编译**，程序里不存在 |
| `if` | **运行时**（单片机跑的时候） | 代码编进去了，跑到这里才判断 |

**本工程用的是普通 `if`**，因为它们更好懂：

```c
if (BENCH_TEST == 1) { 台架测试 }
else                 { 正常工作 }
```

`BENCH_TEST` 是 0 的时候，编译器自己会发现"0==1 永远不成立"，
自动把那段删掉，效果和 `#if` 一样，但你一眼就能看懂逻辑。

### 常用符号速查

| 符号 | 名字 | 例子 | 意思 |
|---|---|---|---|
| `->` | 箭头 | `m->kp` | 和 `(*m).kp` 一样：访问指针指向的结构体的成员 |
| `&` | 取地址 | `&rc_data` | 拿到这个变量在内存里的地址 |
| `*` | 解引用 | `*p` | 拿到指针指向的那个值 |
| `&` | 按位与 | `x & 0x0F` | 只保留低 4 位，其余清零 |
| `\|` | 按位或 | `x \| y` | 把两个数的位"拼"在一起 |
| `<<` | 左移 | `x << 8` | 乘以 256，等于"把数往高位挪" |
| `>>` | 右移 | `x >> 8` | 除以 256，等于"把数往低位挪" |
| `%` | 取余 | `x % 8192` | 除法剩下的余数 |

### 类型名后面的 `_t`

| 类型 | 是什么 | 范围 |
|---|---|---|
| `uint8_t` | 无符号 8 位整数 | 0 ~ 255 |
| `int16_t` | **有符号** 16 位整数 | -32768 ~ +32767 |
| `uint16_t` | 无符号 16 位整数 | 0 ~ 65535 |
| `int32_t` | 有符号 32 位整数 | 约 ±21亿 |

`_t` 只是"type"的缩写，习惯写法。
**有符号（signed）和无符号（unsigned）的区别就是"能不能表示负数"**，
电机的转速可能是负的（反转），所以必须用 `int16_t`。

### `static` 是什么

```c
static Motor_t s_motor[4];
```

意思是"**这个变量只有本文件能用**"。
别的 `.c` 文件看不见它，也改不了它。
好处：不会和别人重名，也不会被乱改。

**加在函数前面**同理：`static void CAN_Send4(...)` 只在本文件内可用。

### `volatile` 是什么

```c
static volatile uint8_t s_new_frame = 0;
```

意思是"**这个变量随时可能被别人改，每次都要真的去内存里读**"。

什么情况必须加？**变量在中断里被改、在主程序里被读**的时候。
不加的话，编译器可能想："这个变量在这个函数里没人改它，
那我读一次存起来就行了"，结果主程序永远看不到中断的修改。

### `memset` 和 `memcpy` 是什么

```c
memset(m, 0, sizeof(Motor_t));                    /* 把一整块内存清 0 */
memcpy(rc_data.buf, BSP_RC_GetFrame(), DBUS_LEN); /* 把 18 字节从 A 拷到 B */
```

| 函数 | 参数 | 作用 |
|---|---|---|
| `memset(地址, 值, 长度)` | 从"地址"开始的"长度"个字节，全部填成"值" |
| `memcpy(目标, 来源, 长度)` | 从"来源"拷"长度"个字节到"目标" |

### `NULL` 和 `0`

在 C 里，指针为空一般写 `0`（或者 `NULL`，`NULL` 本质就是 0）。
所以函数里判断"指针有没有效"，写成：

```c
if (m == 0) { return; }
```

## 三、一帧数据怎么走完全程

```
【第 1 站】接收机 ──串口线──► 串口3 硬件
              （100000 波特率，9 位数据，偶校验，每 14ms 一帧 18 字节）

【第 2 站】DMA 自动搬字节
              每来 1 个字节，DMA 就自动写进 s_dma_buf，一共 18 个
              CPU 完全不参与

【第 3 站】空闲中断
              18 字节送完后线路空闲 → 硬件置 IDLE 标志 → 进串口中断
              bsp_rc.c 的 BSP_RC_IrqHandler() 做 7 件事：
                 ① 确认是空闲中断
                 ② 清 IDLE 标志（不清会死循环）
                 ③ 算这次收了多少字节
                 ④ 停 DMA
                 ⑤ 只有收满 18 字节才 memcpy 到 s_frame
                 ⑥ 记时间戳 s_last_tick
                 ⑦ 重启 DMA（不重启只能收到第一帧！）

【第 4 站】底盘任务来取（每 1ms 一次）
              task_rc.c 的 Task_RC_Loop()
              BSP_RC_TakeNewFrame() 返回 1 → 说明有新数据

【第 5 站】拷进全局 rc_data
              memcpy(rc_data.buf, s_frame, 18)
              关控标志清零

【第 6 站】拆位：18 字节 → 遥杆数值
              drv_dbus.c 的 DBUS_GetChannel(&rc_data, 通道号)
              ch2 = (buf[2]>>6) | (buf[3]<<2) | (buf[4]<<10)
              结果是 364(最小) / 1024(中位) / 1684(最大)

【第 7 站】归一化 + 死区
              (raw - 1024) / 660          → -1.0 ~ +1.0
              绝对值小于 0.08 就当成 0    → 死区，防止车自己爬

【第 8 站】变成物理量
              × CHASSIS_MAX_V    → 前进速度 米/秒
              × STEER_LIMIT_DEG  → 转向角 度

【第 9 站】运动解算
              min 运动解算（ackermann.c，现在是空壳）
              输入：速度 + 转向角
              输出：2 个后轮 rpm + 2 个前轮角度

【第10站】PID ×4
              后轮速度环：误差 = 目标rpm - 实际rpm   → 输出电流
              前轮位置环：误差 = 目标角度 - 实际角度 → 输出电压

【第11站】发 CAN
              0x200 电流帧 → 后轮 3508
              0x1FF 电压帧 → 前轮 6020

【第12站】电调执行 → 轮子转

【第13站】反馈回来，闭环闭合
              电调每 1ms 发 0x201~0x204 / 0x205~0x208
              CAN 中断 → Motor_UpdateFeedback() / Steer_UpdateFeedback()
              下一次 PID 就用上新值了
```

### 关控时会发生什么（`rc_lost_flag = 1`）

```
超过 21ms 没收到新帧
    ↓
task_rc.c 里：
    rc_lost_flag = 1
    DBUS_SetSafeValue(&rc_data)     ← 18 个字节改成"摇杆全回中"
    ↓
task_chassis.c 里：
    不读摇杆 → vx_ms = 0, steer_deg = 0
    后轮：target_rpm = 0  → PID 把车刹停
    前轮：目标【不更新】  → 保持当前角度，不会突然回正
```

**为什么前轮不更新目标？**
阿卡曼车高速转弯时如果突然回正，车会横滑甚至翻车。
所以关控时保持转向角，只停后轮。

## 四、调试变量表

用调试器（或 FreeMASTER）看这些变量，就能知道卡在哪一站：

| 变量 | 在哪个文件 | 正常表现 | 不正常说明什么 |
|---|---|---|---|
| `dbg_last_tick` | task_rc.c | 每 14ms 跳一次 | 不动 → 一帧都没收到（查接线/波特率） |
| `dbg_drop_cnt` | task_rc.c | 一直不动 | 飞快地涨 → 线接触不良 / 干扰 |
| `dbg_b0` ~ `dbg_b5` | task_rc.c | 推摇杆时变化 | 不变 → 数据没进来 |
| `rc_lost_flag` | config.c | 开控 0，关控 1 | 一直是 1 → 时间戳没更新 |
| `DBUS_GetChannel(&rc_data, 2)` | — | 中位 1024，满推 364/1684 | 数值乱 → 位拼接公式错 |
| `Motor_Get(0)->actual_rpm` | drv_motor.c | 手转车轮有数 | 一直是 0 → CAN 没 Start 或过滤器没配 |
| `Motor_Get(0)->give_current` | drv_motor.c | 跟目标变化 | 一直是 0 → PID 没算，或 kp=0 |
| `Steer_Get(0)->actual_raw` | drv_steer.c | 0~8191，掰车轮会变 | 不变 → 6020 反馈没进来 |
| `Steer_Get(0)->have_fb` | drv_steer.c | 1 | 0 → 一帧反馈都没收到 |
| `Steer_Get(0)->limit_hit` | drv_steer.c | 0 | 1 → 顶到限位了，减小 STEER_LIMIT_DEG |
| `hcan2.State` | HAL 内部 | `HAL_CAN_STATE_LISTENING` | 不是 → 没调 HAL_CAN_Start |

## 五、你必须自己标定的东西

| 要标定的 | 在 config.h 第几行附近 | 怎么标 |
|---|---|---|
| 3508 的 ID ×2 | `DRIVE_ID_L` / `DRIVE_ID_R` | 用 C620 上的按键设，然后填进来 |
| 6020 的 ID ×2 | `STEER_ID_L` / `STEER_ID_R` | 同上 |
| 前轮机械中位 ×2 | `STEER_CENTER_L` / `STEER_CENTER_R` | 车轮掰到正前方，读 `Steer_Get(0)->actual_raw` |
| 软件限位角度 | `STEER_LIMIT_DEG` | 量物理极限，减 5 度 |
| 四个方向 | `DRIVE_DIR_L/R`、`STEER_DIR_L/R` | 台架测试，反了就改成 -1.0f |
| 两套 PID | `DRIVE_PID_*`、`STEER_PID_*` | 架空慢慢调，见 config.h 里的调参顺序 |
